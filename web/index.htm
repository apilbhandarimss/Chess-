1. OVERVIEW

A complete object-oriented chess engine written in C++ with Raylib graphics, full legal-move validation, Minimax AI with PeSTO tapered evaluation, and three game modes.

2. ARCHITECTURE

The project is split into four independent modules, each with a header and implementation file, orchestrated by main.cpp.

ModuleDescription
BoardBoard representation, rendering, and mouse-based piece movement. Owns the 8x8 character grid and all game-state flags.
RuleCheckerLegal move validation for all six piece types. Handles castling, en passant, check detection, and self-check prevention.
EngineMove generation and recursive Minimax search. Selects the best move for the AI side at depth 4 plies.
EvaluatorPeSTO tapered evaluation: material values, midgame and endgame piece-square tables, and phase-interpolated scoring.

Module Dependency Graph

main.cpp
  |-- Board          (rendering, input, game state)
  |-- RuleChecker     (move legality)
  |-- Engine          (AI search)
  |     |-- RuleChecker  (generates legal moves)
  |     |-- Evaluator    (scores positions)
  |-- Evaluator       (called at leaf nodes)

3. HOW TO BUILD

The project uses CMake. Ensure Raylib is installed and the 3d_wood/ texture directory sits beside the final executable.

mkdir build
cd build
cmake ..
cmake --build .

NOTE: The 3d_wood/ directory must be copied next to the compiled binary before running. It contains the 12 PNG textures for each chess piece.

5. RULECHECKER MODULE

RuleChecker.cpp / RuleChecker.h - Validates every legal chess move including special rules. Called by both the human input handler and the engine's move generator.

Public API

FunctionSignatureReturns
Piece ownershipisWhitePiece(char)True if A-Z
Piece ownershipisBlackPiece(char)True if a-z
Check detectionisKingInCheck(board, bool)True if king is attacked
Move validationisValidMove(old, new)True if move is fully legal

Internal Helpers

HelperUsed By
isPathClearStraight()Rook, Queen horizontal/vertical
isPathClearDiagonal()Bishop, Queen diagonal

Validation Pipeline

Detect moved piece   (compare old vs new board square-by-square)
  |
Find source / destination
  |
Apply piece-specific rules
  Pawn   -> forward move, double-push, diagonal capture, en passant
  Knight -> L-shape (no path check needed)
  Bishop -> diagonal + isPathClearDiagonal()
  Rook   -> straight + isPathClearStraight()
  Queen  -> both of the above
  King   -> 1-square any direction, castling validation
  |
isKingInCheck(newBoard, side)   <- self-check prevention
  |
Return true / false

Castling Conditions (all must be true)

  • King has never moved (whiteKingMoved / blackKingMoved == false)
  • Correct rook has never moved (whiteRookAMoved / whiteRookHMoved)
  • All squares between king and rook are empty
  • King is not currently in check
  • The king's transit square is not under attack

6. ENGINE MODULE

Engine.cpp / Engine.h - Move generation and Minimax search. Produces the AI's chosen move at a configurable depth.

Functions

FunctionDescription
generateMoves(board, forWhite)Iterates all 64x64 from/to combinations, filters through isValidMove(), auto-promotes pawns to queens.
minimax(board, depth, isWhite)Recursive Minimax. Returns evaluate(board) at depth 0; +/-9999 for checkmate; 0 for stalemate.
engineMove(board)Top-level call - generates moves, runs Minimax at depth 4, returns the best board state.

Search Algorithm

engineMove(board)
  |
generateMoves()   ->  list of candidate board states
  |
for each candidate:
    minimax(candidate, depth=3, opponent)
      |-- depth 0  ->  evaluate(board)
      |-- no moves ->  checkmate (+/-9999) or stalemate (0)
  |
Pick highest score (White) / lowest score (Black)

Terminal State Scores

SituationScore
Checkmate against the maximizing player-9999
Checkmate against the minimizing player+9999
Stalemate0

NOTE: The engine auto-promotes pawns to queens during search to avoid branching on promotion choices, which would multiply the search tree significantly.

7. EVALUATOR MODULE

Evaluator.cpp / Evaluator.h - PeSTO tapered evaluation. Returns a centipawn score (positive = White advantage).

Material Values

PieceMidgameEndgame
Pawn8294
Knight337281
Bishop365297
Rook477512
Queen1025936
King00

Tapered Evaluation Formula

phase = sum PhaseWeight[piece]   // per piece on board (max 24)
score = (mgScore * phase + egScore * (24 - phase)) / 24

Phase weights: Knight=1, Bishop=1, Rook=2, Queen=4. As pieces are traded off, the score smoothly interpolates from midgame tables to endgame tables.

Piece-Square Tables

Each piece has separate 8x8 bonus tables for midgame and endgame. Black's tables are mirrored vertically (row = 7 - row) so the same tables apply symmetrically.

9. DEVELOPMENT LOG

Session 1 - Foundation

Board rendering + pawn-only movement

Established the core project structure. Built the Board class with an 8x8 character grid, the Raylib rendering loop, and mouse-based piece selection. RuleChecker was scaffolded with pawn-only move validation (forward single move, initial double push). Pieces other than pawns were rendered but could not move.

Tags: Board.cpp, RuleChecker.cpp, Pawn movement, Raylib rendering, Mouse input

Session 2 - July 16, 2026

All six pieces + check detection

Extended RuleChecker to support all piece types. Added isWhitePiece(), isBlackPiece(), isPathClearStraight(), and isPathClearDiagonal() helpers. Fixed board-comparison logic so captures (landing on an occupied square) were correctly detected instead of only moves to empty squares. Check detection was next on the list.

Tags: Bishop, Knight, Rook, Queen, King, Capture detection

Session 3

Full rule set, check/checkmate/stalemate, castling, en passant

A large session that completed the entire rule set. Implemented isKingInCheck() scanning all enemy attackers. Added self-check prevention as a final gate in isValidMove(). Both castling variants for both colors (with intermediate-square safety check) and en passant were added. The main loop gained hasAnyLegalMove(), isCheckmate(), and isStalemate(), plus end-game overlay messages. LoadPieceTextures() was introduced.

Tags: isKingInCheck(), Castling, En passant, Self-check prevention, Checkmate, Stalemate, Texture loading

Session 4 - 2026-07-22

Pawn promotion, castling rook movement, main loop refactor

Pawn promotion was fully implemented with a Raylib modal dialog (Queen / Rook / Bishop / Knight). Board state flags isPromoting, promotionRow, and promotionCol pause normal input while the player chooses. Castling rook movement was wired up so the rook physically relocates on the board. Several bugs were fixed: promotion state not clearing, turn switching before selection, and rook not moving. SetTargetFPS(60) added for consistent frame timing.

Tags: Promotion dialog, Promotion state flags, Castling rook move, Bug fixes, 60 FPS cap

Session 5 - 2026-07-29

Minimax AI, move generation, game modes, bot integration

The Engine module was built. generateMoves() enumerates all legal board states for a side. minimax() recursively searches to depth 4, with terminal detection for checkmate and stalemate. engineMove() wraps it and returns the best candidate. The game loop was extended with a GameMode enum, a graphical main menu (PvP / vs Black Bot / vs White Bot), and logic to detect whose turn the bot takes. The evaluator was connected, replacing any earlier placeholder.

Tags: generateMoves(), minimax(), engineMove(), GameMode enum, Main menu, Bot integration

Session 6 - latest

PeSTO tapered evaluation - midgame/endgame interpolation

The evaluator was upgraded from simple material counting to a PeSTO-inspired tapered evaluation. Separate midgame and endgame piece values were added alongside all twelve piece-square tables. A game-phase counter tracks remaining material (max 24 phase points). The final score is blended: (mg * phase + eg * (24 - phase)) / 24. Black's tables are mirrored vertically. The engine now makes positionally-aware decisions throughout the game - rewarding centralized knights, active rooks, and king safety in endgames.

Tags: PeSTO tables, Phase interpolation, Midgame values, Endgame values, Board mirroring

Search

Evaluation

  • Passed, isolated, doubled, and backward pawn detection

  • King safety + pawn shield
